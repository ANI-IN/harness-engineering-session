# Control task: Show user details in project member lists

A small change to an existing response model.

## Behaviour

Project member items gain three fields taken from the member's user: `email`, `name`, and `role`
(`admin`, `member`, or `viewer`). The fields show the user's current values. They appear in:

- each item of `GET /projects/{project_id}/members`, and
- the response of `POST /projects/{project_id}/members`.

The existing fields (`project_id`, `user_id`, `added_at`), ordering, pagination, roles, and audit rows
are unchanged. The response model in the OpenAPI schema (`MemberOut`) lists the new fields.

## Where the change goes

`app/api/schemas.py`, `app/api/members.py`, `app/services/members.py`, and tests in
`tests/visible/`.

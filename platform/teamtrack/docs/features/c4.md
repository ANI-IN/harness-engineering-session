# Control task: Store issue titles without surrounding whitespace

A small change to existing write endpoints.

## Behaviour

Issue titles are stored with leading and trailing whitespace (spaces, tabs, newlines) removed, and
responses show the stored title. This applies to `POST /projects/{project_id}/issues`,
`PATCH /issues/{issue_id}`, and the board's create and edit forms (`/board/projects/{project_id}/issues`
and `/board/issues/{issue_id}/edit`), which use the same service functions.

- The 1 to 200 character limit applies to the title after trimming. A title that is longer than 200
  characters only because of surrounding whitespace is accepted.
- A title that is empty after trimming gives 422 `validation_error`, as before.
- Whitespace inside the title is kept. Other fields are unchanged.
- Roles, audit rows, and the other house rules apply as before: viewers get 403 `forbidden`, and each
  successful write adds one audit row.

## Where the change goes

`app/api/schemas.py`, `app/services/issues.py`, and tests in `tests/visible/`.

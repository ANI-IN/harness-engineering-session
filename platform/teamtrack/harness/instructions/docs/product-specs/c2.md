# Control task: Search projects by name

A small change to an existing list endpoint.

## Behaviour

`GET /projects` accepts an optional `q` query parameter of 1 to 100 characters. With it, the list
contains only the caller's org's projects whose name contains `q`, ignoring case. `q` is plain text:
characters such as `%` and `_` match themselves. Without `q`, the list is unchanged.

- An empty `q`, or one longer than 100 characters, gives 422 `validation_error`.
- The search works with `cursor` and `limit` as every list does (House rule 3: API conventions): keyset pagination by
  ascending id, and a cursor from a search page continues the search. When nothing matches, the
  response is `{"items": [], "next_cursor": null}`.
- Archived projects are never listed, as before. Projects of another org never appear (House rule 1: Tenant isolation). Any role
  may read the list.

## Where the change goes

`app/api/projects.py`, `app/services/projects.py`, `app/repositories/projects.py`, and tests in
`tests/visible/`.

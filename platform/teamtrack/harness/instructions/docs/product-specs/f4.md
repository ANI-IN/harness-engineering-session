# Feature 4: Version checks on issue edits

Status: planned. Section 4: Verification.

## Goal

Two people editing the same issue never silently overwrite each other. On the board, and for API
clients that name the version they edited, the second save is refused and the person reloads. Each
issue also shows its change history.

## API

- `GET /issues/{issue_id}` returns the header `ETag: "<version>"`, the issue's version in double
  quotes, for example `ETag: "3"`.
- `PATCH /issues/{issue_id}`, `POST /issues/{issue_id}/assign`, and `POST /issues/{issue_id}/transition`
  accept an optional `If-Match: "<version>"` header:
  - no `If-Match` header: the change is applied as before;
  - the current ETag: the change is applied;
  - any other value: 412 `precondition_failed`, and nothing changes. This covers an older or newer
    version and a malformed value (an empty value, a version without the double quotes, a weak
    `W/"3"` tag, or text that is not a version).
- Every successful change through these endpoints makes `version` go up by one, and the response
  carries the new `ETag`, with or without `If-Match`.
- Check order: 401 (no token), 403 (viewer), 404 (another org's or a deleted issue), then 412, then 422
  (an invalid body, or a status change that is not allowed). For example a member who sends an invalid
  body with a stale `If-Match` gets 412, and the same body without `If-Match` gets 422.
- The 412 response is documented in the OpenAPI schema of the three endpoints. 428 is not used.
- A refused write (403, 404, 412, 422) adds no audit row.
- `GET /issues/{issue_id}/history` lists the issue's audit entries (entity `issue`, that issue's id)
  oldest first, as `AuditOut` items in the list envelope with `cursor` and `limit` (keyset by audit id).
  Any role may read it. Another org's or a deleted issue gives 404.

A request without `If-Match` changes the issue as it did before this feature, so existing clients and
tests keep working unchanged.

## Board

The edit form on the issue page sends the version it was loaded with in a hidden field named
`version`. A save whose version is not the current one (or has no version) changes nothing and
returns HTTP 409 with an HTML page (an element with class `conflict`) that says the issue was changed
by someone else and links back to the issue. A save with the current version works as before.

## Out of scope

Weak ETags, `If-None-Match`, versions on other resources, merging edits.

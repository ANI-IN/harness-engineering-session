# Feature 7: Labels

Status: planned. Final project (two sessions).

## Goal

Teams tag issues with their own labels (for example "bug") and filter issue lists by label.

## API

| Endpoint | Result |
|---|---|
| `GET /labels` | list of `LabelOut` of the caller's org |
| `POST /labels` with `{"name", "color"}` | 201 and the new `LabelOut` |
| `PATCH /labels/{label_id}` with `{"name"?, "color"?}` | 200 and the updated `LabelOut` |
| `DELETE /labels/{label_id}` | 204; the label is also removed from every issue |
| `POST /issues/{issue_id}/labels` with `{"label_id"}` | 200 and the issue's `IssueOut` |
| `DELETE /issues/{issue_id}/labels/{label_id}` | 204 |

- `LabelOut` is `{"id", "org_id", "name", "color"}`. `name` is 1 to 50 characters; `color` is
  `#rrggbb` (six hexadecimal digits, upper or lower case). Other values are 422
  `validation_error`.
- Names are unique per org, ignoring case: creating or renaming to a name another label of the org
  already has (in any case) gives 409 `label_exists`. Other orgs may use the same name.
- `IssueOut` gains `labels`: a list of `{"id", "name", "color"}` ordered by label id, on every endpoint
  that returns issues.
- Adding a label the issue already has returns 200 and changes nothing. Removing a label the issue does
  not have gives 404 `not_found`. Labels do not change the issue's `version`.
- Members and admins write; viewers get 403 `forbidden`. Any role reads.
- Another org's label or issue gives 404 `not_found`, also when the label id is in the body. A deleted
  issue, or an issue in an archived project, gives 404.
- `GET /projects/{project_id}/issues` and `GET /issues` (where org-wide search exists) accept a
  `label_id` query parameter: only issues carrying that label are listed. A label of another org gives
  404.
- `GET /labels` uses the list envelope with `cursor` and `limit`, keyset by ascending label id.
- `POST /labels` accepts `Idempotency-Key` (House rule 4: Safe retries); keys are scoped per org and endpoint.
- Audit: `label.create`, `label.update`, `label.delete` (entity `label`) and `issue.label_add`,
  `issue.label_remove` (entity `issue`, the issue's id), one row per successful write. Refused writes
  and adding a label the issue already has add none.

## Data

- New tables `labels` and `issue_labels` in exactly one new Alembic migration on the current head.
- Seed, with stable ids: three labels per org, `bug` (`#d73a4a`), `feature` (`#a2eeef`), `docs`
  (`#0075ca`). Acme: labels 1, 2, 3. Globex: labels 4, 5, 6. Each org's second issue carries `bug`;
  each org's third issue carries `bug` and `feature`.

## Out of scope

Label descriptions, labels on projects, the board.

# Feature 2: Comments on issues

Status: planned. Section 2: State and sessions (two sessions).

## Goal

Team members discuss an issue on the issue itself, in the API and on the web board.

## API

| Endpoint | Result |
|---|---|
| `POST /issues/{issue_id}/comments` with `{"body": "..."}` | 201 and the new `CommentOut` |
| `GET /issues/{issue_id}/comments` | list of `CommentOut`, oldest first |
| `DELETE /comments/{comment_id}` | 204 |

`CommentOut` is `{"id", "org_id", "issue_id", "author_id", "body", "created_at"}`; `author_id` is the
user who wrote it.

- `body` is 1 to 5000 characters; anything else is 422 `validation_error`. Unknown fields are 422.
- Writing (POST, DELETE) needs a writer: viewers get 403 `forbidden`. Any role may read the list.
- Only the comment's author or an admin of the org may delete a comment. Anyone else gets 403
  `forbidden`.
- Another org's issue or comment gives 404 `not_found`. A deleted issue, or an issue in an archived
  project, gives 404 on all three endpoints, including deleting one of its comments.
- A deleted comment is gone: it is no longer listed, and deleting it again gives 404.
- The list uses the envelope `{"items": [...], "next_cursor": ...}` with `cursor` and `limit` (1 to
  100, default 20), keyset by ascending comment id, which is oldest first.
- `POST` accepts `Idempotency-Key` (House rule 4: Safe retries, `services.idempotency.run_once`):
  the same key and body return the first response and create nothing; the same key with another body gives 409
  `idempotency_conflict`. Keys are scoped per org and per request path.
- Audit (House rule 5: Audit log): creating adds one row `comment.create`, deleting adds one row
  `comment.delete`, both with entity `comment` and the comment's id. A refused write or a replay adds
  none.

## Data

- New table `comments` (`id`, `org_id`, `issue_id`, `author_id`, `body`, `created_at`) in exactly one
  new Alembic migration whose `down_revision` is the current head (House rule 7: Migrations).
- Seed: two comments per org on the org's first issue, with stable ids. Acme issue 1: comment 1 by the
  member, then comment 2 by the admin. Globex issue 21: comment 3 by the member, then comment 4 by the
  admin.

## Board

The issue page (`/board/issues/{issue_id}`) shows a comments panel: a `section` with class `comments`,
one element with class `comment` and a `data-comment-id` attribute per comment, oldest first, and, for
writers only, a form with class `add-comment` that posts a `body` field to
`/board/issues/{issue_id}/comments` and returns to the issue page. Comment text is shown escaped.
Viewers see the comments but no form.

## Out of scope

Editing comments, mentions, notifications.

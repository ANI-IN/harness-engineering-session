# Feature 1: Org-wide issue search

Status: planned. Section 1: Instructions.

## Goal

Users find issues across every project of their organization from one list, with filters, instead of
opening each project's issue list.

## API

`GET /issues` lists the caller's org's issues across its projects.

| Query parameter | Type | Rule |
|---|---|---|
| `status` | `open`, `in_progress`, `done` | optional |
| `priority` | `low`, `medium`, `high` | optional |
| `assignee_id` | integer, 1 or more | optional; a user of the caller's org |
| `project_id` | integer, 1 or more | optional; an active project of the caller's org |
| `q` | string, 1 to 100 characters | optional; case-insensitive substring of the title |
| `cursor`, `limit` | as every list | `limit` 1 to 100, default 20 |

- Filters are optional and combine with AND. Without filters the list holds every live issue of the
  org.
- `q` matches a substring of the title, ignoring case. Every character in `q` is literal: `%` and `_`
  match only themselves.
- Deleted issues and issues of archived projects are never listed.
- A `project_id` or `assignee_id` that is not in the caller's org gives 404 `not_found`, exactly as if
  it did not exist. An archived project's id also gives 404.
- An invalid value (an unknown status or priority, a non-integer id, an empty or too long `q`, a
  `limit` outside 1 to 100) gives 422 `validation_error`.
- Any role may read (admin, member, viewer). Without a token: 401.
- The response is the list envelope `{"items": [...], "next_cursor": ...}` with keyset pagination by
  ascending issue id (`app/api/pagination.py`). Items are `IssueOut`, the same shape as
  `GET /issues/{issue_id}`. Following `next_cursor` with the same filters walks every matching issue
  exactly once.
- Reads add no audit rows.

## Notes

- The legacy `GET /v1/issues` handler is not filtered by org and uses offset pagination. Do not copy
  it (HANDBOOK "Legacy /v1 API").
- House rules 1 to 7 apply (HANDBOOK). Existing endpoints keep their behaviour.

## Out of scope

Sorting options, full-text search, searching descriptions.

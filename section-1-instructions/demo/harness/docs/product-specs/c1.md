# Control task: Filter the user list by role

A small change to an existing list endpoint.

## Behaviour

`GET /users` accepts an optional `role` query parameter: `admin`, `member`, or `viewer`. With it, the
list contains only the users of the caller's org that have that role. Without it, the list is
unchanged.

- Any other value gives 422 `validation_error`.
- The filter works with `cursor` and `limit` as every list does (House rule 3: API conventions): keyset pagination
  by ascending id, and a cursor from a filtered page continues the filtered list. When nothing
  matches, the response is `{"items": [], "next_cursor": null}`.
- Any role may read the list, as before. Users of another org never appear (House rule 1: Tenant isolation).

## Where the change goes

`app/api/users.py`, `app/services/users.py`, `app/repositories/users.py`, and tests in
`tests/visible/`.

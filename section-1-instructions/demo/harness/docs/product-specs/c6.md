# Control task: Filter the audit log by action

A small change to an existing list endpoint.

## Behaviour

`GET /audit` accepts an optional `action` query parameter of 1 to 50 characters. With it, the list
contains only the caller's org's audit rows whose action name equals `action` exactly (for example
`issue.create`). Without it, the list is unchanged.

- An empty `action`, or one longer than 50 characters, gives 422 `validation_error`.
- The filter works with `cursor` and `limit` as every list does (House rule 3: API conventions): keyset pagination by
  ascending id, and a cursor from a filtered page continues the filtered list. When nothing matches,
  the response is `{"items": [], "next_cursor": null}`.
- Reading the audit log stays admin-only (others get 403 `forbidden`). Rows of another org never
  appear (House rule 1: Tenant isolation).

## Where the change goes

`app/api/audit.py`, `app/services/audit.py`, `app/repositories/audit.py`, and tests in
`tests/visible/`.

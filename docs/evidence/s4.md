hash, and capture detail that the Section 4 pages rely on. The pages name a source or a result in a
few words and link to an anchor here. The score records and run logs behind the run ids are kept with
the course's private run records, not in this repository, except the Assignment 4 reference run,
whose files are in `section-4-verification/assignment/solution/live/`. Finding ids point to the course's
research notes, where each quote was checked against the source text.

<a id="s4-show-4-settings"></a>

**Demo setting for `make show-4` (2026-10-18), not a comparison**

`make show-4` runs the harness arm alone, so it shows the mechanism; it measures nothing. Since
2026-10-18 one setting differs from `make demo-4`:

- `MAX_TESTS=3` (`--max-tests 3`): the test filters run on the first three tests the test phase
  proposes, in file order and then source order. Any further test is removed from the workspace
  with the reason "not filtered: this demo filters only the first 3 proposed tests" and counts as
  discarded. `make show-4 MAX_TESTS=` filters every test.
- Why: with five to seven proposed tests the filters took 5 to 9 minutes of the run.
- Guard rails: the CLI refuses `--max-tests` for an A/B (`test_the_test_cap_is_refused_for_an_ab`
  in `platform/tests/unit/ab/test_single_arm.py`), and only `make show-4` passes it
  (`test_only_show_4_caps_the_filtered_tests` in `platform/tests/unit/test_makefile.py`).

Everything else (task, layers, profile, turn budgets, referee) is what `make demo-4` uses. The
speed-ups that apply to every run are in
[general.md](general.md#demo-speed-2026-10-18).

<a id="s4-course-design"></a>

**Course design, not source claims**

- **The verify gate.** The course composes A2's clean state (F-a-84), A4's strict verifier
  (F-a-127), and A3's separate judge (F-a-110) into one gate on `finish(claim="done")`. The gate's
  items are `GATE_CHECKS` in `platform/src/shipharness/harness/verify/gate.py`.
- **House rules R1 to R7.** The course's name for A1's "golden principles" (F-a-99), enforced like
  A1's custom lints (F-a-96).
- **Filters 4 and 5.** Course filters with no source sentence of their own. Filter 5 is a composite of
  B11's "no regression, by construction" (F-b-22) and A2's rule against editing tests (F-a-80).
- **Filter 3's mutant branch.** From ACH (F-b-32, F-b-40); TestGen-LLM's filter 3 is coverage only
  (F-b-20).
- **Two disjoint mutant sets.** A filter set and a referee set that share no mutation (`overlaps` in
  `platform/src/shipharness/filters/mutant_sets.py`). Hand-written mutants, not mutmut, so they can
  target chosen lines.
- **Blinded reviewer.** "Blinded" is A/B design: `blind()` in
  `platform/src/shipharness/reviewer/blind.py` removes arm traces from the diff. The reviewer runs on
  both final diffs, never inside the gate.
- **Primary measure for F4.** All hidden tests and all referee mutants, registered before any run.
- **Counts, not percentages.** Every run is a dot.
- **Assignment 4.** House rule R8 (soft delete), filter 6 (no duplicate test, after B11's later
  dedup filter, F-b-26; ignoring renamed locals is a course addition), and the grading criteria were
  designed for this course.

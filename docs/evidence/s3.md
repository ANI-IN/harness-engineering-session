## How to use this page

This is the Section 3 part of the evidence page. It holds every run id, A/B id, finding id, commit
hash, and capture detail that the Section 3 pages rely on. The pages name a source or a result in a
few words and link to an anchor here. The score records and run logs behind the run ids are kept with
the course's private run records, not in this repository, except the Assignment 3 reference run,
whose evidence is in `section-3-scope-sandbox/assignment/solution/live/`. Finding ids point to the course's
research notes, where each quote was checked against the source text.

<a id="s3-course-design"></a>

**Course design, not source claims**

- **Allowed paths per phase.** The sources state the principle: A5's "File operations restricted to
  the project directory only" (F-a-86) and A1's "enforce boundaries centrally, allow autonomy locally"
  (F-a-98). The per-phase lists come from each dataset line's `outputs.allowed_paths`.
- **Only the harness sets `passes`.** A2 lets the coding agent set it after "careful testing"
  (F-a-108). The course moves the decision to the harness, citing A3 (F-a-110). The fields
  `evidence` and `testedAt` are course additions to A2's entry (F-a-82).
- **Revert by byte snapshot.** A composite of A2's git revert (F-a-57) and A5's blocking hook
  (F-a-87); the harness reverts, with no git involved.
- **The sandbox values.** One container per arm, the same for both arms, with the flags in
  `platform/src/shipharness/sandbox/policy.py`. Flag behaviour is from the Docker docs (D24 to D30).
- **The cause "nothing limits what the agent changes".** No single source sentence states it. The
  pages show its supports side by side: A1 F-a-20, A4 F-a-18 and F-a-19, A5 F-a-86, A6 F-a-21.
- **Assignment 3.** The history rule, the rule order in `check_diff`, the status consistency checks,
  and the grading criteria were designed for this course.

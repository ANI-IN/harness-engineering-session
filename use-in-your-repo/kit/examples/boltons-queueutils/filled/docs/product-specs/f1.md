# Feature 1: The docstrings of peek and pop name the error they raise

Status: next.

## Goal

A caller who reads the docstring of `peek` or `pop` learns the error an empty queue really raises.
Today both docstrings say `KeyError`, while both methods raise `IndexError`. The last line of the
traceback from
`python -c "from boltons.queueutils import HeapPriorityQueue; HeapPriorityQueue().pop()"`:

```
IndexError: pop on empty queue
```

## Behaviour

- `peek()` and `pop()` on an empty queue raise `IndexError`, for `HeapPriorityQueue` and
  `SortedPriorityQueue`. This does not change.
- `peek(default)` and `pop(default)` on an empty queue return `default`. This does not change.
- The docstrings of `peek` and `pop` name `IndexError`.
- A test pins `IndexError` for both methods and both queue classes.

## Out of scope

Changing which error is raised; the abstract base class (`docs/PLANS.md`).
